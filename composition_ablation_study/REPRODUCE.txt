RERUN WITHOUT OVERWRITING THE ORIGINAL STUDY

  python -m composition_ablation_study.copy_protocol \
    --study /content/cs585_composition_ablation_20261126/study_v1/study.json \
    --out /content/cs585_composition_ablation_repeat

Then run the serial queue:

  python -u -m composition_ablation_study.run_queue \
    --study /content/cs585_composition_ablation_repeat/study.json \
    --out /content/cs585_composition_ablation_repeat/queue

In another process, finish.py waits for THAT existing queue and then runs the
complete audit, uncontended batch 1 timing, aggregate analysis and figures:

  python -u -m composition_ablation_study.finish \
    --study /content/cs585_composition_ablation_repeat/study.json

The queue is intentionally serial. It refuses existing outputs and does not
automatically resume a missing process. An observation timeout is not a reason
to relaunch a job. Check authoritative liveness and counts using:

  python -m composition_ablation_study.progress \
    --root /content/cs585_composition_ablation_repeat

ANALYSIS, FIGURES AND REPORT

After all 84 cells complete:

  python -m composition_ablation_study.audit --study STUDY_JSON \
    --out STUDY_ROOT/final_audit.json --require-complete
  python -m composition_ablation_study.analyze --study STUDY_JSON \
    --out STUDY_ROOT/aggregate
  python -m composition_ablation_study.representatives --study STUDY_JSON \
    --out STUDY_ROOT/aggregate/representatives

finish.py already performs audit, timing and aggregate figures, so do not run
those concurrently with the GPU sweep. Timing requires all 84 cells terminal.
The representative renderer reads native records on-host; its PDF/PNG paths
are rasterized within vector axes and never exported as coordinate arrays.
It renders canonical success/failure examples, a compact preview, and a separate
lowest-initial-disagreement failure diagnostic. The latter is selected from
failures and is not an estimate of their frequency.

To rebuild the report from the delivered aggregate evidence, extract
aggregate_results_and_figures.zip into a fresh directory EVIDENCE_DIR and
editable_latex_and_figures.zip into EDITABLE_DIR. With this package on PYTHONPATH:

  python -m composition_ablation_study.build_report \
    --aggregate EVIDENCE_DIR/aggregate \
    --latency EVIDENCE_DIR/latency/summary.json \
    --audit EVIDENCE_DIR/protocol/final_audit.json \
    --study EVIDENCE_DIR/protocol/study.json \
    --representatives EVIDENCE_DIR/aggregate/representatives \
    --findings EDITABLE_DIR/findings.json --out FRESH_REPORT_DIR

FRESH_REPORT_DIR must not exist. From that new directory, compile:

  tectonic latent_composition_ablation_report.tex

Alternatively, the delivered editable LaTeX can be compiled directly beside its
figures directory. The builder uses only Python's standard library; analysis and
figure generation require the numerical/native environment listed above.
Native rollout elapsed times include physics/recording and occasional CPU
checkpoint work. Use the separate uncontended matched batch-one benchmark
for inference-speed comparisons.
All percentages and table entries come from the aggregate JSON; conclusions
are explicitly limited to the existing banks and one frozen model pair.
